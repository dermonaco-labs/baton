# Data model: Spec Kit 1.3.0 migration

**Feature**: `004-speckit-1-3-0-migration` | **Plan**: [plan.md](plan.md) | **Research**: [research.md](research.md)

This feature adds no runtime data store. The entities are repository files and lock rows.

## Spec Kit pin (`baton.lock.json` → `upstreams.speckit`)

| Field | Value after migration | Rule |
|-------|-----------------------|------|
| `version` | `1.3.0` | Exact; FR-001 |
| `tag` | `v1.3.0` | `v` + version |
| `commit` | `91261fdcf1738cb095a31ff5bee145f502e3af91` | Full tag commit |
| `requirements` | `baton/upstream/specify-cli.requirements.txt` | Unchanged path |
| `requirements_sha256` | sha256 of the regenerated hash-locked file | Includes transitive packages |

`baton/upstream/specify-cli.requirements.in` holds exactly `specify-cli==1.3.0\n`.

## Pack file entry (`packs/<id>.yml` → `files[]`)

Existing fields: `from`, `path`, `upstream_path`, `role`, `x-*`. New optional field:

| Field | Type | Rule |
|-------|------|------|
| `extension` | `"github"` | Allowed only when `from: speckit`. Routes the source to the bundled-extension tree. No other value. |

`packs/issues.yml` after migration:

```yaml
schema: 1
id: issues
description: Opt-in GitHub issue creation from tasks.md (Spec Kit github extension).
requires: [core]
conflicts: []
files:
  - { from: speckit, extension: github, path: .github/skills/speckit-github-taskstoissues/SKILL.md }
  - { from: speckit, extension: github, path: .specify/extensions/github/extension.yml }
  - { from: speckit, extension: github, path: .specify/extensions/github/README.md }
  - { from: speckit, extension: github, path: .specify/extensions/github/commands/speckit.github.taskstoissues.md }
  - { from: speckit, extension: github, path: .specify/extensions/github/scripts/bash/resolve-tasks.sh }
  - { from: speckit, extension: github, path: .specify/extensions/github/scripts/powershell/resolve-tasks.ps1 }
  - { from: speckit, extension: github, path: .specify/extensions/github/scripts/python/resolve_tasks.py }
  - { from: baton, path: .github/skills/speckit-taskstoissues/SKILL.md }
```

Invariants:

- No `core` entry and no `core` lock row has an install path under `.specify/extensions/github/` or the skill
  `speckit-github-taskstoissues` (FR-009).
- `.specify/extensions.yml` and `.specify/extensions/.registry` stay `core`-owned and unchanged by this pack.

## Vendored lock row (`baton.lock.json` → `files[]`)

For each `extension: github` entry, sync writes:

| Field | Value |
|-------|-------|
| `path` | install path, e.g. `.specify/extensions/github/extension.yml` |
| `upstream` | `speckit` |
| `upstream_path` | the same path in the extension tree |
| `stored_at` | `packs/issues/files/<path>` |
| `sha256_upstream`, `sha256` | hash of the generated bytes (no repair) |
| `license` | `MIT` |
| `repair` | `null` |
| `packs` | `["issues"]` |
| `x-speckit-extension` | `github` |

The 1.0.11 row for `packs/issues/files/.github/skills/speckit-taskstoissues/SKILL.md` is removed: that path becomes
the authored wrapper, which has no lock row.

## Compatibility wrapper (Baton-authored)

| Attribute | Value |
|-----------|-------|
| Source | `baton/skills/speckit-taskstoissues/SKILL.md` |
| Stored at | `packs/issues/files/.github/skills/speckit-taskstoissues/SKILL.md` |

| References | exactly one skill reference: `/speckit-github-taskstoissues` |

Behavior is defined in [contracts/issues-pack.md](contracts/issues-pack.md).

## Trusted path (feature 003 bindings)

`isTrusted(storedPath)` is true when any of these holds:

1. `storedPath === HOOKS_PATH` (unchanged);
2. `storedPath` starts with a `BOUND_ROOTS` entry (unchanged);
3. a base- or candidate-lock row for `storedPath` carries `x-baton-source` (unchanged);
4. **new:** `targetOf(storedPath).path` starts with a `BOUND_ROOTS` entry;
5. **new:** a base- or candidate-lock row for `storedPath` carries `x-speckit-extension`.

`FROZEN_FIELDS` gains `x-speckit-extension`. Rules 4 and 5 only add trusted paths. No path that is trusted today
becomes untrusted.

## Install manifest (`.baton/manifest.json`, adopter side)

No schema change. For `issues` adopters:

- `.github/skills/speckit-taskstoissues/SKILL.md` changes owner from `speckit` to `baton`;
- the seven extension files are added with owner `speckit` and pack `issues`.

`src/commands/adopt.mjs` writes `upstreams.speckit = "1.3.0@91261fd"`.
