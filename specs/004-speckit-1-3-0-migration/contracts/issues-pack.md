# Contract: `issues` pack on Spec Kit 1.3.0

**Feature**: `004-speckit-1-3-0-migration` | **Requirements**: FR-006–FR-011, FR-014, SC-004, SC-005

## Install surface

| Selection | Installed issue-creation files |
|-----------|--------------------------------|
| `core` only | None: no `speckit-taskstoissues` skill, no `speckit-github-taskstoissues` skill, nothing under `.specify/extensions/github/` |
| `core` + `issues` | `.github/skills/speckit-taskstoissues/SKILL.md` (wrapper), `.github/skills/speckit-github-taskstoissues/SKILL.md`, and the six files under `.specify/extensions/github/` |

- With either selection, `.specify/extensions.yml` and `.specify/extensions/.registry` have the same bytes and
  hooks. Baton does not register the `github` extension, so `specify extension list` does not show it.
- With `--script sh`, the extension skill calls `.specify/extensions/github/scripts/bash/resolve-tasks.sh`.
  With `--script ps` or `--script py`, init installs the flavour rendering of that skill (generated by the pinned
  `specify-cli`), which calls the matching script. All three script files are installed in every flavour.
- Every installed file has a manifest row with its sha256, pack `issues`, and owner: `speckit` for extension files,
  `baton` for the wrapper.

## Wrapper behavior: `/speckit-taskstoissues`

1. The skill frontmatter names `speckit-taskstoissues` and describes it as a compatibility alias for
   `/speckit-github-taskstoissues`.
2. Precondition: if `.github/skills/speckit-github-taskstoissues/SKILL.md` is absent, the agent stops and reports:
   "`/speckit-github-taskstoissues` is not installed. Install Baton's `issues` pack, which ships Spec Kit's `github`
   extension; `/speckit-taskstoissues` only delegates to it." The agent attempts no other way to create issues.
3. Otherwise the agent runs `/speckit-github-taskstoissues` with the user's original arguments unchanged and follows
   that skill's instructions.
4. The wrapper body contains no issue-creation step. It has no GitHub tool names (`issue_write`, `list_issues`), no
   `gh issue` command, and no script invocation.

## Closure

- `validatePackClosure` for `core` reports 0 issues.
- `validatePackClosure` for `issues` (`requires: [core]`) reports 0 issues:
  - the wrapper's reference to `speckit-github-taskstoissues` resolves in `issues`;
  - the extension skill's reference to `speckit-converge` resolves in `core`;
  - its reference to `speckit-git-commit` is the `excluded:C5` optional reference inherited from `core`.
- `sync` and `sync --check` raise `E_DANGLING_REF` if any of these breaks.

## Update from a 1.0.11 `issues` install

- An unmodified `.github/skills/speckit-taskstoissues/SKILL.md` is replaced in place by the wrapper.
- A modified copy is kept and reported as a conflict with a `.new` copy, which is existing behavior.
- The seven new files are added under the existing rules for new managed files.
- No file is orphaned, and no manual removal step is needed. Update logic is unchanged (Q2 = X).

## Upgrade automation (feature 003)

A Spec Kit candidate that changes, deletes or adds any of the following is rejected as manual-review:

- a stored path whose install target is under `.specify/extensions/` or `.specify/presets/`;
- a row that carries `x-speckit-extension`.

The wrapper is never an allowed regenerated output. Existing bindings are unchanged.
